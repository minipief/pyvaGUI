# Design Decisions

| ID | Date | Decision | Reason | Alternatives considered | Consequences |
| --- | --- | --- | --- | --- | --- |
| D-001 | 2026-10-13 | Treat installed pyva-toolbox 1.3.1 as authoritative for implementation signatures. | The local calculation environment is the runtime target and signatures can be inspected directly. | Guess from examples or use online documentation alone. | Record signatures in `pyva_api_notes.md`; revisit if the dependency version changes. |
| D-002 | 2026-10-13 | Represent plate and mass perforations using pyva `PerforatedLayer`, built from the stored hole radius and distance. | `PlateLayer` and `MassLayer` accept a perforation object; pyva accepts `hole_radius` and `distance` in its perforation constructor. | Store a pyva object in the model or calculate porosity separately. | Keep JSON data as plain SI values and let pyva calculate square-pattern porosity. |
| D-003 | 2026-10-13 | Keep `f_start`, `f_end`, and `n_points`; generate `n_points` logarithmically spaced frequencies. | The user chose to preserve all three settings even though the resulting samples are not exact third-octave centers. | Use only third-octave center frequencies derived from the endpoints. | Frequency labels match the generated samples; do not describe them as exact third-octave centers. |
| D-004 | 2026-10-13 | Pass host-layer thickness to `PerforationSpec.to_pyva(thickness)`. | pyva uses perforation thickness in its transfer resistance and reactance. | Store a separate perforation thickness or use a fixed thickness. | `LayerSpec.build()` supplies its own thickness; this clarifies the prompt's unspecified method parameter. |
| D-005 | 2026-10-13 | Keep calculation results in memory and out of project serialization. | Results are transient outputs, not project configuration. | Persist result arrays in the project JSON. | Result containers can be passed to plotting and export without changing the project format. |
| D-006 | 2026-10-13 | Store projects as format-version 1 JSON without file paths, modified flags, or results. | Those values are runtime state rather than project configuration. | Persist all runtime metadata. | Loading always starts with an unmodified project and results are recalculated. |
| D-007 | 2026-10-13 | Return imported library materials with new IDs without automatically adding them to the library. | Import and library mutation are separate operations; the caller can review before adding and saving. | Import and persist materials in one operation. | Library workflows explicitly call `add()` and `save()` when committing an import. |
| D-008 | 2026-10-13 | Remap poroelastic frame IDs when the matching frame is in the same import file. | Both imported materials receive new identifiers and must still reference one another. | Keep the original frame ID in every imported poroelastic spec. | An omitted frame ID remains available for `Project.missing_frame_material_id()`. |
| D-009 | 2026-10-13 | Use lowercase CSV view identifiers; write phase in degrees. | These names map directly to result-tab choices and make exported units explicit. | Export raw complex values or use UI-only translated labels as input. | Complex values become real-valued magnitude, phase, real, or imaginary columns. |
| D-010 | 2026-10-13 | Support PNG and SVG image export based on the filename extension. | These are the required formats and are both supported by Matplotlib. | Accept every format recognized by the local Matplotlib installation. | Unsupported extensions fail with a clear `ValueError`. |
| D-011 | 2026-10-13 | Use a horizontal `QSplitter` for the model and results panels and put the log below them. | This follows the agreed main-window layout and lets users resize the two work areas. | Fixed-width panels or a separate log window. | The initial window stays simple and establishes the layout used by later phases. |
| D-012 | 2026-10-13 | Store each model object's ID in its tree item's `Qt.ItemDataRole.UserRole`. | Display names are not guaranteed to be unique or stable. | Use visible text to find project objects. | UI actions can resolve objects by ID without parsing labels. |
| D-013 | 2026-10-13 | Rebuild the project tree from project model lists after load or save. | A full refresh keeps the model as the single source of truth. | Mutate individual tree rows in each project workflow. | The tree is always derived from the current project. |
| D-014 | 2026-10-13 | Edit materials on a deep copy and commit only after successful validation. | Cancel must leave the project object unchanged. | Bind widgets directly to the project object. | Dialog validation can gather all errors without corrupting project data. |
| D-015 | 2026-10-13 | Allow material-type selection only when creating a new material. | Changing an existing type can break layer and solver references. | Replace the referenced object while changing type. | Existing material editing preserves its class and identifier. |
| D-016 | 2026-10-13 | Ask before copying a missing poroelastic frame material from the library. | The user decides whether the extra dependency belongs in the project. | Silently add the frame or leave an unexplained broken reference. | Accepted frame copies receive new IDs and poroelastic references are remapped. |
| D-017 | 2026-10-13 | Normalize known legacy material-library references in memory when loading/importing. | Existing user libraries reference base fluids and poroelastic frames using obsolete fields and aliases. | Reject the file or rewrite it automatically during load. | Existing values remain available to current specs while source JSON remains untouched until an explicit save. |
| D-018 | 2026-10-13 | Display layer thickness and perforation dimensions in millimeters while storing meters. | This matches the agreed layup mockup and keeps model values in SI. | Show meters in the editor. | Conversion is confined to the GUI helpers `mm_to_m` and `m_to_mm`. |
| D-019 | 2026-10-13 | Reorder layer models on drop and rebuild all table cell widgets. | Qt's default row move does not move widgets installed with `setCellWidget`. | Depend on Qt to preserve row widgets during an internal move. | `Layup.move_layer()` remains authoritative and the table is refreshed after a move. |
| D-020 | 2026-10-13 | Draw stack layers in stored incident-to-receiving order and color them by material family. | The preview should match the direction and material distinction in the mockup. | Draw in reverse order or use one color for all layers. | Layer zero is at the top and fluid, porous, and solid families remain visually distinct. |
| D-021 | 2026-10-13 | Reserve a minimum visible height and list labels for thin layers below the stack. | Very thin layers would otherwise disappear or become unreadable. | Scale every layer strictly by thickness. | Preview geometry is readable even when actual thickness ratios are extreme. |
| D-022 | 2026-10-13 | Create one result placeholder tab per solver before calculation features are available. | Solver configuration and tab identity need to exist before workers and charts are implemented. | Delay all tabs until the plotting phase. | Phase 12/13 can fill the tab associated with the solver ID instead of changing navigation structure. |
| D-023 | 2026-10-13 | Run solver calculations in a QObject moved to QThread and communicate by signals. | Synchronous pyva calculations would block the GUI event loop. | Run calculations directly in a button handler or use a more complex async system. | The worker owns copied model data, never widgets, and cancellation occurs between layups. |
| D-024 | 2026-10-13 | Use separate subplots for selected complex impedance views and one real-valued axis for other solvers. | Magnitude, phase, real, and imaginary values have different units/scales and need clear labels. | Overlay unrelated views on one axis. | Impedance defaults to magnitude and phase; the user can add or remove views. |
| D-025 | 2026-10-13 | Connect worker-originated GUI updates to bound MainWindow slots, not lambdas that touch widgets. | Bound QObject receivers allow Qt to queue updates onto the GUI thread safely. | Update widgets from worker callbacks. | Worker progress, log, result, and error handlers run on the GUI thread. |
| D-026 | 2026-10-14 | Use `.pyvagui` as the project filename extension while retaining the format-version 1 JSON document unchanged. | Give project files a distinct application extension without changing project data or migration semantics. | Introduce a new binary/container format or alter the serialized project schema. | Project dialogs use `.pyvagui`; file association can be added separately later. |
